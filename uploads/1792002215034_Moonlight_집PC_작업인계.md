## 사용자 목적과 현재 상태

- 사용자는 현재 PC에서 Moonlight로 집 PC의 Sunshine에 접속하려 한다.
- 사용자는 현재 망의 중간 네트워크 장비가 서버 인증서를 교체한다고 설명했다. 이 원인은 아직 직접 검증되지 않았다.
- 접속 시 401 오류가 발생해 TLS 비활성화를 고려했다.
- 비교 대상으로 준 AutoHotkey 코드를 확인한 결과, 해당 코드는 TLS를 끄는 대신 서버 인증서 오류 검사를 생략한다.
- 현재 PC의 성능 때문에 실제 소스 수정 및 빌드는 집 PC에서 진행하기로 했다.
- 현재까지 Moonlight 소스 다운로드, 코드 수정, 개발 도구 설치 또는 빌드는 하지 않았다. 접속 문제도 아직 해결되지 않았다.

## 확인한 로컬 파일

아래 경로는 현재 PC 기준이다. 집 PC에서는 같은 경로가 없을 수 있다.

- 비교용 AutoHotkey 파일: `E:/-D조/송명진/SynologyDrive/통합자동화_v3/Lib/HttpSession.ahk`
- 실행 중인 Moonlight: `C:/Users/user/Documents/Codex/문라이트/MoonlightPortable-x64-6.2.0/Moonlight.exe`
- 확인한 로그: `C:/Users/user/Documents/Codex/문라이트/MoonlightPortable-x64-6.2.0/Moonlight-1791985545.log`

현재 채팅의 작업 폴더에는 Moonlight 로그가 없었고, 실행 중인 프로세스의 경로를 확인해 위 로그를 찾았다. 로그 원문에는 주소와 페어링 관련 값이 있으므로 이 문서에는 복사하지 않았다. 다음 작업에서도 개인 키, 인증서 저장 설정, 페어링 비밀값 또는 전체 요청 URL을 공개 출력하지 않는다.

## AutoHotkey에서 확인한 사실

```ahk
this.Http := ComObject("WinHttp.WinHttpRequest.5.1")
this.Http.Option[4] := 13056
```

`Option[4]`는 `WinHttpRequestOption_SslErrorIgnoreFlags`이다. `13056 = 0x3300`이며 다음 오류 플래그의 조합이다.

| 플래그 | 무시하는 오류 |
|---|---|
| `0x0100` | 알 수 없는 CA 또는 신뢰하지 않는 루트 |
| `0x0200` | 인증서 용도 오류 |
| `0x1000` | 서버 이름 불일치 |
| `0x2000` | 인증서 유효기간 오류 |

HTTPS/TLS 암호화 자체는 유지한다. 이 코드가 다른 사내 HTTP 요청에서 작동했다는 사실만으로 Moonlight에서도 해결된다고 단정할 수 없다.

공식 문서: https://learn.microsoft.com/en-us/windows/win32/winhttp/winhttprequestoption

## 로그에서 확인한 사실

두 번의 페어링 시도에서 동일한 흐름을 확인했다.

1. HTTP로 `serverinfo` 요청.
2. HTTP로 `getservercert`, `clientchallenge`, `serverchallengeresp`, `clientpairingsecret` 단계 진행.
3. 마지막 HTTPS `/pair` 요청의 `phrase=pairchallenge`에서 실패.
4. 오류: `QNetworkReply::SslHandshakeFailedError`.

관련 로그 줄은 첫 시도 141–147, 두 번째 시도 150–156 부근이다. 앞선 기본 포트 HTTP 요청에는 시간 초과도 있었지만, 이후 사용자가 입력한 다른 포트에서는 페어링 절차가 진행됐다. 포트 변경 이유나 집 공유기 매핑은 확인하지 않았다.

이 로그에는 상세 `QSslError`, 실제 수신 인증서의 발급자 또는 TLS 실패 원인 문자열이 없다. 인증서 교체, TLS 호환성 문제, 클라이언트 인증 실패 중 어느 것인지 이 로그만으로 확정할 수 없다.

## 공식 소스에서 확인한 내용

공식 PC 저장소: https://github.com/moonlight-stream/moonlight-qt

현재 설치본에 맞춰 먼저 사용할 기준 태그: `v6.2.0`.

이전 조사에서 네트워크 코드의 세부 동작은 주로 `master` 소스로 확인했다. 구현 전 반드시 `v6.2.0`의 실제 코드를 다시 확인한다. 아래 줄 번호는 master 기준으로 변경될 수 있다.

### Moonlight

대상 파일: `app/backend/nvhttp.cpp`

https://github.com/moonlight-stream/moonlight-qt/blob/master/app/backend/nvhttp.cpp

- `NvHTTP::handleSslErrors()`는 저장된 서버 인증서와 오류에 포함된 인증서를 비교하고, 조건이 맞을 때만 SSL 오류를 무시한다.
- `NvHTTP::openConnection()`은 요청에 `IdentityManager`의 SSL 설정을 넣어 클라이언트 인증서를 사용한다.
- `SslHandshakeFailedError`가 발생하면 `GfeHttpResponseException(401, "Server certificate mismatch")`로 변환한다. 따라서 사용자 화면의 401이 실제 서버 HTTP 401이 아닐 수 있다.
- 앱 목록·실행·종료 등에도 HTTPS 요청이 있다. 페어링 요청 하나를 HTTP로 바꾸는 것만으로 전체 동작이 해결되지는 않는다.

페어링 코드: https://github.com/moonlight-stream/moonlight-qt/blob/master/app/backend/nvpairingmanager.cpp

### Sunshine

https://github.com/LizardByte/Sunshine/blob/master/src/nvhttp.cpp

Sunshine은 Moonlight의 클라이언트 인증서도 검사한다. 중간 장비가 TLS를 종료하고 새 TLS 연결을 만드는 구조라면 Moonlight의 서버 인증서 검사만 생략해도 Sunshine 쪽 인증에서 실패할 수 있다. 집 PC의 Sunshine 버전과 해당 버전 소스도 확인한다.

서버 인증서 검사를 생략하면 중간 장비가 HTTPS 요청 내용을 읽거나 바꿀 수 있다. 사용자의 목적은 본인 PC 간 접속이며, 이 변경의 영향을 설명한 상태다.

## Windows 빌드 환경

조사 시 공식 `v6.2.0` README에 기재된 요구 사항이다. 실제 작업 시 태그와 설치 가능한 도구 조합을 다시 확인한다.

https://github.com/moonlight-stream/moonlight-qt/tree/v6.2.0#building

| 도구 | 용도 및 설정 |
|---|---|
| Git | 소스 및 서브모듈 다운로드 |
| Visual Studio 2026 | Community 가능. C++ 데스크톱 개발 워크로드, MSVC, Windows SDK 준비 |
| Qt 6.11 이상 | MSVC용 x64 구성. 공식 안내상 MinGW 미지원 |
| Qt Creator | 선택 사항. 프로젝트 열기 및 빌드에 편리 |
| 7-Zip | 배포 패키지 생성 시 필요 |
| Windows Graphics Tools | Debug 빌드를 실행할 때 필요 |

현재 PC에서는 Git만 확인됐다. Visual Studio 및 Qt는 기본 위치와 PATH에서 발견하지 못했으며, 다른 경로의 설치까지 배제한 것은 아니다. 집 PC 환경은 아직 조사하지 않았다.

기본 준비 명령:

```powershell
git clone --branch v6.2.0 --recurse-submodules https://github.com/moonlight-stream/moonlight-qt.git
cd moonlight-qt
.\setup-deps.ps1
```

스크립트 내용을 먼저 읽고 실행한다. 프로젝트의 `AGENTS.md` 등 적용되는 작업 지침도 확인한다.

Qt Creator에서 `moonlight-qt.pro`를 열고 MSVC x64 Kit를 선택해 Release 빌드를 할 수 있다. 배포 파일 생성은 공식 `scripts/build-arch.bat`와 `scripts/generate-bundle.bat`를 읽어 정확한 인자와 전제 조건을 확인한 뒤 진행한다. 실행 파일 하나만 복사하면 Qt 및 기타 DLL이 누락될 수 있다.

## 다음 작업 순서

1. 집 PC의 Git, Visual Studio C++ 도구, Qt 설치와 CPU 아키텍처 확인.
2. 공식 `v6.2.0` 소스를 별도 작업 폴더에 준비하고 변경 전 빌드가 가능한지 확인.
3. 해당 태그의 SSL 처리, 페어링 및 설정 저장 방식을 검토.
4. 인증서 오류 종류·오류 설명·인증서 발급자 등의 진단을 추가. 개인 키와 페어링 비밀값은 기록하지 않음.
5. 기본값은 기존 검증을 유지하고, 사용자가 명시적으로 활성화하는 서버 인증서 검사 생략 옵션을 구현. 가능하면 대상 호스트로 범위를 제한.
6. 클라이언트 인증서 전송은 유지. 서버 인증서 검사와 클라이언트 인증을 구분.
7. Release 빌드 및 필요한 런타임 파일을 별도 폴더로 패키징. 원본 설치본과 설정·페어링 정보를 덮어쓰지 않음.
8. 집 내부망에서 기본 기능과 옵션 동작을 확인. 이 결과만으로 문제의 망에서 해결됐다고 보고하지 않음.
9. 문제가 발생한 망에서 재시험해 상세 오류와 Sunshine 로그를 비교. 클라이언트 인증 문제가 남으면 그 증거를 바탕으로 다음 해결책을 결정.

사용자는 이번 요청에서 인계 문서 작성을 요청했다. 이 문서의 작업 순서는 다음 세션을 위한 제안이며, 이번 세션에서 구현 또는 설치까지 완료했다는 뜻은 아니다.
