# 부산교통공사 XPlatform 선로출입관리 HTTP 분석 요약

작성일: 2026-07-15  
대상 시스템: `https://mis.humetro.busan.kr/FS/`  
대상 업무: XPlatform 9.2.1 선로출입관리 (`LA`)

> 이 문서에는 세션 쿠키, 실제 SSO 사용자 식별자, 비밀번호 및 조회 결과의 개인정보를 기록하지 않는다.

## 1. 결론

- XPlatform 프로그램을 직접 조작하지 않아도 일반 HTTP 요청으로 선로출입관리 데이터를 조회할 수 있다.
- 단, `mis.humetro.busan.kr`에서 발급된 유효한 로그인 세션이 필요하다.
- 통합포털 로그인만으로 충분하다고 단정할 수는 없다. 선로출입관리 링크의 SSO 절차를 거쳐 MIS용 세션이 만들어져야 한다.
- MIS 세션이 만들어진 뒤에는 XPlatform을 열어 두지 않아도 HTTP POST 요청으로 조회할 수 있다.
- XPlatform은 화면 표시, Dataset 직렬화 및 엑셀 생성을 담당하는 클라이언트이며, 실제 조회는 서버의 `.do` 엔드포인트가 수행한다.

## 2. 확인된 실행 흐름

1. 통합포털에서 로그인한다.
2. 다음 링크로 선로출입관리를 실행한다.

   ```text
   https://mis.humetro.busan.kr/FS/index.jsp?gv_selSystGubn=LA
   ```

3. 브라우저에서 다음 페이지를 순서대로 호출한다.

   ```text
   /FS/index.jsp
   /FS/xui/install.jsp
   /FS/xui/install/x_installChromeSSO.jsp
   ```

4. 브라우저가 로컬 XPlatform 런처를 호출한다.

   ```text
   https://127.0.0.1:7936/launcher/xplatform/...
   ```

5. 런처가 XPlatform 9.2.1과 다음 시작 파일을 사용한다.

   ```text
   https://mis.humetro.busan.kr/FS/xui/XUI.xadl
   ```

6. 실제 서비스 기본 주소는 다음과 같다.

   ```text
   https://mis.humetro.busan.kr/FS/
   ```

## 3. 인증과 세션

- 직접 HTTP 조회에는 MIS 도메인의 유효한 세션 쿠키가 필요하다.
- 현재 분석에서는 Edge에서 내보낸 HAR의 세션을 메모리에서만 읽어 사용했다.
- XPlatform 실행 과정에서 전달되는 SSO 식별자는 메뉴 및 사용자 초기화에 사용된다.
- 메뉴 초기화 요청은 다음과 같다.

  ```text
  POST /FS/ssoLogin.do
  queryId=login.userSSOSelect
  ```

- 이미 초기화된 유효한 MIS 세션에서는 `procSelect.do`를 직접 호출해도 정상 응답을 받았다.
- 세션 만료 시 XPlatform 공통 코드에서 `ErrorCode=-99999`를 세션 종료로 처리한다.
- HAR는 활성 세션 쿠키와 사용자 식별정보를 포함할 수 있으므로 자격증명 파일처럼 취급해야 한다.

## 6. LA10100 일반 화면 조회

일반 화면의 조회 버튼은 다음 요청을 사용한다.

```text
POST https://mis.humetro.busan.kr/FS/procSelect.do
Content-Type: text/xml; charset=UTF-8
queryId=LA10100.search
```

조회 파라미터:

| 파라미터 | 의미 | 전체 조건 |
|---|---|---|
| `IN_START_DATE` | 시작일 | 필수 날짜 |
| `IN_END_DATE` | 종료일 | 필수 날짜 |
| `IN_LINE_CODE` | 호선 | 빈 문자열 |
| `IN_STST_CODE` | 시작역 | 빈 문자열 |
| `IN_FNST_CODE` | 종료역 | 빈 문자열 |
| `IN_REQU_BSCD` | 요청부서 코드 | 빈 문자열 |
| `IN_WORK_CODE` | 작업구분 | 빈 문자열 |
| `IN_STUS` | 상태 | 빈 문자열 |

응답 Dataset:

```text
ds_out → 화면 Dataset ds_fsmsliacxm
```

실제 검증 결과:

- HTTP `200`
- `ErrorCode=0`
- `ErrorMsg=SUCC`
- 결과 없는 미래 날짜 조회에서도 정상 XML Dataset 응답 확인

## 7. 요청부서 필터

화면에 표시되는 부서 전체 경로는 서버 조회 요청에 전달되지 않는다.

예시 표시값:

```text
기술혁신본부/전기사업소/전로부/호포전기분소
```

실제 요청값:

```text
IN_REQU_BSCD='2612021'
```

따라서 다음과 같이 처리한다.

- 특정 요청부서 조회: 부서코드만 전달
- 전체 요청부서 조회: `IN_REQU_BSCD`를 빈 문자열로 전달
- 부서명 및 전체 조직 경로: 요청에 불필요
- 로그인 세션과 메뉴 권한: 별도로 필요

## 8. 일반 조회와 엑셀 조회의 차이

엑셀 버튼은 화면에 표시된 일반 조회 Dataset을 그대로 저장하지 않는다. 서버에 엑셀 전용 조회를 다시 요청한다.

| 구분 | 일반 화면 조회 | 엑셀 전용 조회 |
|---|---|---|
| 엔드포인트 | `/FS/procSelect.do` | `/FS/selectList.do` |
| `queryId` | `LA10100.search` | `LA10100.searchExcel` |
| 화면 Dataset | `ds_fsmsliacxm` | `ds_fsmsliacxm00` |
| 확인된 서버 응답 열 수 | 46개 | 54개 |
| `CNAP_BSNM` | 없음 | 있음 |

엑셀 생성 흐름:

1. `LA10100.searchExcel` 호출
2. 응답 `ds_out`을 `ds_fsmsliacxm00`에 저장
3. 숨겨진 엑셀용 그리드 `grd_excel`에 연결
4. `gfn_excelDown()`으로 엑셀 생성

첨부 Excel의 승인 관련 매핑:

```text
운행관제승인부서 ← CNAP_BSNM
운행관제승인사번 ← CNAP_USER
운행관제승인자   ← CNAP_NAME
운행관제승인일자 ← CNAP_DATE

확인부서         ← CONF_BSNM
확인자사번       ← CONF_USER
확인자           ← CONF_NAME
확인일자         ← CONF_DATE
```

`운행관제승인부서`는 XPlatform이 다른 열에서 계산한 값이 아니다. 엑셀 전용 서버 응답에 `CNAP_BSNM`으로 포함되어 내려온다. 서버가 `CNAP_BSCD`를 이용해 부서명을 조회하는 것으로 보이지만, 정확한 SQL 조인 방식은 서버 소스 없이는 확정할 수 없다.

## 10. 재사용 절차

1. Edge에서 사내 통합포털에 정상 로그인한다.
2. 선로출입관리 링크의 SSO 절차를 실행해 MIS 세션을 만든다.
3. XPlatform은 데이터 조회 시 반드시 열려 있을 필요는 없다.
4. 세션이 만료됐으면 새 HAR를 로컬에 저장하거나 다른 안전한 방식으로 MIS 세션을 갱신한다.
5. HAR에서 쿠키 값을 코드나 로그에 출력하지 않고 메모리에서만 읽는다.
6. 원하는 용도에 따라 다음 요청을 선택한다.

   ```text
   일반 화면과 같은 결과: procSelect.do + LA10100.search
   엑셀과 같은 확장 결과: selectList.do + LA10100.searchExcel
   ```

7. 응답의 `ErrorCode`를 확인하고 `Dataset id="ds_out"`을 파싱한다.
8. 세션 오류 또는 로그인 HTML이 반환되면 포털 로그인 및 MIS SSO를 다시 수행한다.

## 11. 보안 및 운영 주의사항

- HAR 파일을 외부에 공유하거나 Git 저장소에 커밋하지 않는다.
- 쿠키, SSO 식별자, 사번, 전화번호를 로그에 출력하지 않는다.
- 조회 권한이 있는 데이터와 업무 목적 범위에서만 사용한다.
- 대량 조회 시 기간을 나누고 요청 간격을 두어 서버 부하를 제한한다.
- 저장·승인·삭제 기능은 `procAction.do` 등의 별도 엔드포인트를 사용하므로 자동화 대상에서 제외한다.
- 세션이 끝난 뒤 포털 로그아웃으로 쿠키를 무효화한다.
- 결과 파일에는 이름과 연락처 등 업무상 개인정보가 포함될 수 있으므로 접근 권한과 보관 기간을 관리한다.

## 12. 다음 구현 권장사항

재사용용 조회 도구를 만들 경우 다음 입력만 받도록 구성하는 것이 적절하다.

```text
- HAR 파일 경로
- 시작일 / 종료일
- 호선 코드
- 시작역 / 종료역 코드
- 요청부서 코드
- 작업구분 코드
- 상태 코드
- 일반 조회 또는 엑셀 전용 조회 선택
- 결과 CSV/XLSX 경로
```

도구는 다음 원칙을 지켜야 한다.

- 세션 값 비저장 및 비출력
- 조회 전용 엔드포인트만 허용
- 응답 오류 코드 검증
- 행 수와 조회 조건만 로그에 기록
- 개인정보가 포함된 원문 응답은 임시파일로 남기지 않음
- CSV 수식 주입 방지 및 XLSX 텍스트 형식 보존
